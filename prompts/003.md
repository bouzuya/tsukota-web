# 003

不明事項についての回答は次の通りです。これらを解決した上で、改めて docs/SPEC.md を読み、不明瞭な点を確認してください。質問リストは `prompts/004.md` に書き込んでください。

## 認証関連

1. 認証フロー: Firebase Auth UID を使用するとあるが、バックエンド（Rust）でのセッション管理方法は？（JWT / Cookie セッション？）

JWT にしてください。

2. 「Google 等」: Google 以外の OAuth プロバイダーも初期対応するか？

対応しません。

## アカウント共有

3. 招待方法: メンバー招待はどのように行うか？（メールアドレス指定？招待リンク共有？）

一旦はデータベースの書き換えで対応するため、保留してください。

4. 権限管理: オーナーとメンバーの権限の違いは？（メンバーはアカウント削除やメンバー管理が不可？）

オーナーはアカウントを削除でき、メンバーを追加・削除できます。

5. 承認フロー: 招待を受けた側の承認プロセスはあるか？

ある想定ですが、保留してください。

## カテゴリ関連

6. デフォルトカテゴリ: 具体的な初期カテゴリ一覧は？

空にしてください。すべてのユーザーは自身でのカテゴリー作成から開始します。

7. カテゴリ削除時: 紐づく Transaction の処理は？（削除不可 / 未分類へ移動 / カテゴリ null 化？）

値を維持してください。削除は一覧に表示せず、新規の取引では選択不可にします。

## 収支記録・レポート

8. フィルタ条件: 取引一覧の具体的なフィルタ条件は？（日付範囲、カテゴリ、type など）

取引フィルタは初期バージョンでは追加しないでください。

9. ページング仕様: 1ページの件数、デフォルトソート順は？

1ページは 20 件。日付の降順です。

10. レポート期間: サマリーや月別推移の期間指定パラメータは？

月別の合計金額・その内訳として月別取引別の合計金額を表示します。

## その他

11. ユーザー情報編集: displayName や photoURL はユーザーが編集可能か？

displayName は編集可能。

photoURL は不要なので `docs/SPEC.md` から削除してください。

12. エラーレスポンス形式: API エラー時のレスポンス形式は？

エラーのレスポンスは RFC 9457 に従う想定です。
