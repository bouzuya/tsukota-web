# 047

- 方針を一部転換します
- すべての use case について `*Request` を URL パス・リクエストボディを考慮して分割するのをやめます
- `docs/SPEC.md` を見直し、更新系操作についてはリソースベースのパスの採用を避けます
    - 更新系 use case については `POST /commands/{use_case_name}`
        - use_case_name は snake_case を使用します
        - HTTP メソッドは POST に固定します
        - リクエストボディに対象や操作内容などのパラメーターを含めます
    - 参照系 use case についてはリソースベースのパスを維持します
        - HTTP メソッドは GET に固定します
        - 例: `GET /accounts/{account_id}`
        - 例: `GET /accounts/{account_id}/categories`
- 判断理由
    - 対象 (パス) と操作内容 (ボディ) で入力が分散するのを避けるため
    - 対象が複数になるような操作での迷いを避けるため
    - 参照系 use case は HTTP GET はリクエストボディを取らないため、入力の分散の問題が起きないため
    - 今回は SPA ではあるものの、なるべく MPA でも動くクラシックな Web アプリケーションとして動作するパス設計にしておきたいため
